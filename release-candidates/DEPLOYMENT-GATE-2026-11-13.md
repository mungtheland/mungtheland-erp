## 배포 전 필수 게이트
1. 운영자에게 **운영 코드 변경에 대한 명시적 승인**을 받는다.
2. 운영 스프레드시트 및 Apps Script 현행 소스의 배포 직전 백업을 생성·검증한다. 스프레드시트 백업만으로 스크립트 소스가 복구되지는 않는다.
3. 운영 Apps Script 프로젝트 ID 및 배포 대상 `.clasp.json`을 실제 운영 프로젝트와 대조한다. **격리 테스트용 `.clasp.guardian-test.json`은 운영에 사용하지 않는다.**
4. 운영 코드 최신 상태를 다시 읽고 `src/PassAdjust.js`와 실제 배포본의 차이 및 충돌을 확인한다. 다른 운영자의 변경이 있으면 중단한다.
5. 후보 파일에서 테스트 주입 코드, 테스트 ID, 테스트용 스프레드시트 참조가 없음을 재검증한다.
6. 운영 시트 헤더·중복 ID·이력 정합성 읽기 전용 검사를 재실행한다. 오류가 있으면 배포 중단.
7. **후보 파일을 운영 소스에 반영하는 변경만** 별도 리뷰/승인한다. 테스트 파일은 포함하지 않는다.
8. 승인된 배포 방식으로 운영 Apps Script에 반영하고 배포 버전 및 시각을 기록한다. 웹앱 배포 갱신 필요 여부도 확인한다.

## 배포 후
- 먼저 운영 읽기 전용 preflight 재실행.
- 실제 고객 데이터에 임의 차감/복구를 실행하지 않는다. 운영에서 쓰기 검증이 필요하면 별도 승인된 테스트 계정/예약과 복원 계획을 마련한다.
- 오류 발생 시 즉시 신규 차감 작업을 중단하고 운영 코드 백업으로 복귀한다. 데이터 변경이 이미 발생했다면 감사 이력과 시트 상태를 대조한 후 복구한다.
- 복귀 후 무결성 검사를 재실행하고 결과를 기록한다.
