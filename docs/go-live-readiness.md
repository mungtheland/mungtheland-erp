## 검증 범위 및 제한
- 운영 원본에 시험 고객·예약·매출을 만들지 않는다.
- CI의 개별 회귀 테스트는 독립된 인메모리 모의 환경에서 실행된다. 예약→등원→이용권 차감→하원→회계→정산을 **한 시나리오로 연계한 E2E 검증**과는 다르다.
- GitHub Actions `verify.yml`의 성공은 Apps Script 운영 배포, 권한, 실제 이메일 발송 및 Google Drive 정기 백업 성공을 보증하지 않는다.

## 현재 확인된 사실
- GitHub의 `deploy.yml`은 검사 후 `clasp push --force`를 실행하며, 기존 웹앱 버전을 자동 갱신하지 않는다.
- 웹앱 버전 29가 배포되었고 화면·탭 전환은 사용자 확인 완료.
- 웹앱은 `mungtheland@gmail.com` 계정으로 실행, 접근은 `나만`. 공용 계정 1개로 운영하기로 결정.
- 수동 백업 1회 성공(9개 탭). 매일 21시 백업 및 23시 누락 감시 트리거 등록 확인.
- 백업 보존 미리보기는 파일 1개를 보존하고 삭제 후보 0개를 반환. 실제 삭제 기능 없음.
- 정기 백업 성공, 알림 메일 수신, 복원 리허설은 아직 검증되지 않았다.

## 운영 승인 체크리스트
- [ ] 운영 계정에 2단계 인증 및 복구 수단 설정. 공유 계정 사용자는 내부 작업자 식별이 불완전하므로 중요한 작업에 별도 작업자 기록 필요.
- [ ] 웹앱 URL을 다른 Google 계정의 비로그인/로그인 브라우저에서 열었을 때 접근 차단되는지 확인(개인정보 입력 없이).
- [ ] 기존 웹앱 배포 버전 및 `나만` 접근 권한 유지 확인.
- [ ] 실제 자동 백업 첫 실행 후 Drive 파일 생성·실행 로그 확인.
- [ ] 실패 알림은 운영 장애를 일으키지 않는 별도 테스트로 이메일 수신 확인.
- [ ] 백업 사본에서 탭·수식·숨김 이력·복원 가능한 데이터 검증. **원본 덮어쓰기 금지**.
- [ ] 예약→등원→이용권 수동 차감→하원→회계→정산 단일 흐름의 격리 통합 테스트를 추가하고 통과 확인.
- [ ] 취소·중복 클릭·차감 실패·지급 중복·정산 복구 예외를 단일 흐름에서 재검증.
- [ ] 실제 서비스 개시 전에 고객정보 수집·보관·접근·파기 정책 확정.

## 운영 절차
1. 영업 시작 전: 전일 백업 파일 확인, 웹앱 접속 및 오늘 예약 조회.
2. 등원 시: 예약·반려견 확인 후 등원 처리.
3. 이용권: 등원 상태와 유효 이용권 확인 후 **운영자가 수동 차감**. 자동 차감 가정 금지.
4. 하원 시: 등·하원 시간 및 출석상태 확인.
5. 거래 발생 시: 실제 입출금 기준으로 회계 입력. 이용권 판매와 매출 자동 연동을 가정하지 않는다.
6. 정산 시: 회계 원장 대조, 미지급/기지급 구분, 지급은 실제 송금 후 기록.
7. 마감 시: 예약·이용권·회계 누락 확인, 21시대 자동 백업 및 23시대 감시 결과 확인.
