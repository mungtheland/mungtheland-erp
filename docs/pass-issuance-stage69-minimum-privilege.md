# 69단계 최소 권한과 운영 접근 경계

기준 커밋은 `cb798863dd1ec214fc3993ad408a9990df1b895f`입니다. 동일 Google 계정 유지 조건에서 확정하는 현재 실행 방식은 **로컬 합성 데이터 검증 전용**입니다. 보호 환경과 원격 프로젝트의 현재 상태를 보존하고 TEST 워크플로를 비활성 상태로 유지합니다. [후보 번들 정적 감사](pass-issuance-stage69-bundle-permission-audit.md) · [환경과 배포 절차](pass-issuance-environment-provisioning.md)

## 권한과 적용 가능한 통제

현재 후보의 유일한 Sheets 접근은 `SpreadsheetApp.openById`입니다. 공식 메서드 요구 범위인 `https://www.googleapis.com/auth/spreadsheets`는 읽기·쓰기 범위이며 단일 워크북으로 한정되지 않습니다. 현재 후보의 요청 범위 추정, 실제로 부여된 권한, 앱이 수행하는 호출은 별도로 검토합니다. 명시적 OAuth 범위를 추가해도 같은 계정의 운영 워크북 소유권은 유지되고, 이 호출을 유지하면서 범위 문자열만 읽기 전용으로 바꾸면 후보 설계와 메서드 요구 범위가 맞지 않습니다. [Google SpreadsheetApp 메서드 참조](https://developers.google.com/apps-script/reference/spreadsheet/spreadsheet-app)

- 실행 프로젝트와 요청 워크북의 고정 SHA-256 지문을 확인한 뒤에만 워크북을 열고, 반환 ID까지 확인한 뒤 탭 이름만 읽습니다. 대상 바꿔치기, 잘못된 반환 ID 및 운영·Guardian ID는 모의 검증의 차단 대상입니다.
- TEST 번들에는 운영 저장 어댑터가 포함되지 않으며 저장 진입점은 비활성입니다. 동적 호출 및 추가 서비스·저장 경로는 생성 번들의 AST 회귀 검사로 점검합니다. 변경된 코드에는 새 검토가 필요합니다.
- 전용 워크플로에서 두 대상 ID와 TEST 전용 번들만 허용합니다. 보호 환경의 브랜치 제한과 관리자 우회 비활성은 기존 API 증빙으로 확인했습니다. 독립 필수 검토자와 TEST 전용 환경 인증은 아직 준비되지 않았습니다. 리터럴 false 조건과 업로드 단계 부재를 유지합니다.
- 별도의 TEST 인증값은 운영 배포 인증과 분리해 관리할 수 있지만, 같은 Google 사용자가 인증하면 그 값만으로 운영 워크북 ACL이 달라지지는 않습니다. 효과적인 OAuth 부여와 실행 주체는 현재 미확인입니다.

## 승인 C와 배포 후보 연결 설계

1. 승인 기록은 C 참조, 승인한 Git 전체 SHA, 업로드할 단일 번들의 SHA-256과 파일별 목록, 두 대상의 고정 지문, 승인자와 독립 검토자, 요청자, 복구 담당자, 검토 일자, 요청 OAuth 범위, 실행 주체와 유효 권한에 대한 근거, 사전 백업의 참조를 함께 보존합니다. 승인 범위는 해당 정확한 리비전의 TEST 프로젝트 코드 배포입니다.
2. 미래 활성화 변경은 보호된 워크플로와 고정된 커밋을 사용하고 요청자가 제공한 문자열을 승인 근거로 신뢰하지 않습니다. 검토자에게 보여준 동일 번들 바이트를 보존해 배포하거나, 고정 환경에서 재생성하고 해시가 같은 경우에만 사용합니다. 해시는 정적 감사의 파일명 순서, 구분자, UTF-8 인벤토리 규칙을 따릅니다. 운영체제나 줄바꿈에 따른 바이트 차이는 배포 전 불일치로 차단합니다.
3. 업로드 직전에 승인 기록의 SHA와 번들 해시, 고정 두 대상, 보호 환경 및 독립 검토 조건을 대조합니다. 하나라도 누락되거나 불일치하면 중단합니다. 사전 백업은 전용 프로젝트에만 한정합니다. 별도로 승인된 업로드 이후 독립 조회로 원격 파일, 매니페스트와 진입점 상태를 대조합니다. 과거 후보 해시는 예시 증빙으로 보존하며 이번 결정에서 승인 대상으로 채택하지 않습니다.

승인 **B**는 지정된 TEST 워크북에 V2 원장 탭과 승인된 헤더를 초기화하는 별도 작업입니다. 승인 **C**는 고정된 후보 소스의 TEST Apps Script 배포를 대상으로 합니다. 하나를 다른 쪽의 승인으로 사용하지 않습니다. 발급, 픽스처 데이터 쓰기 및 운영 변경은 각각의 승인 범위를 따릅니다.

## 70단계 결정

현 제약에서는 **BLOCKED**입니다. 당장 가능한 작업은 고정 후보의 로컬 재현 및 모의 검증, 승인 기록 초안과 사전·사후 확인 체크리스트 작성, 운영 배포 대상의 비공개 증빙 검토입니다. Google 실행과 원장 생성은 이 작업에 포함되지 않습니다.

1. **동일 계정과 현재 게이트 유지.** 합성 검증만 계속합니다. 운영 접근 차단을 증명할 수 없으므로 실제 원장 초기화와 배포를 진행하지 않습니다.
2. **동일 계정으로 실증이 꼭 필요한 경우.** 원격 코드 검증만 필요한 후보는 Sheets 접근 모듈을 빼고 합성 스냅샷만 쓰는 구성을 별도로 설계할 수 있습니다. 원장 초기화가 목적이면 전용 워크북 한 곳의 대상 검증과 초기화만 담당하는 좁은 작업으로 따로 설계합니다. 권한 있는 결정권자가 각각의 대체 설계와 보완 통제로 계정 수준 잔여 위험을 수용할 수 있는지 검토해야 합니다. 승인된 대체 정책이 있다면 별도 변경과 독립 검증이 필요합니다. 현재 게이트는 대체 통제를 승인된 격리의 대용으로 인정하지 않습니다. 승인 B나 C만으로 이 차단을 해제하지 않습니다.
3. **계정 수준 격리가 필수인 경우.** 운영 데이터에 권한이 없는 별도 실행 주체가 필요합니다. 새 계정을 만들지 않는 현재 결정에서는 이 경로를 채택할 수 없습니다.
