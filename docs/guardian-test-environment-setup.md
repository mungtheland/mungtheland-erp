# 보호자 웹 기능 테스트 환경 분리 가이드

**운영 스크립트 및 운영 스프레드시트에서 테스트 함수를 실행하지 마세요.**

1. 운영 스프레드시트와 별개의 **빈 테스트 스프레드시트**를 만든다. 실제 보호자 개인정보를 복사하지 않는다.
2. 별도 Apps Script 테스트 프로젝트를 만든다. 운영 스크립트의 배포 ID와 혼용하지 않는다.
3. 테스트 프로젝트의 스크립트 속성 `MD_GUARDIAN_TEST_SPREADSHEET_ID`에 테스트 시트 ID를 입력한다.
4. `mdGuardianTestSetupCheck_`는 테스트 시트 3종(고객·반려견관리, 예약·등하원관리, 보호자등원요청)의 존재 여부만 확인한다. 생성하거나 데이터를 수정하지 않는다.
5. 테스트 시트의 보호자등원요청 헤더: 요청 ID | 예약 ID | 반려견 ID | 고객 ID | 식사 희망시간 | 사료 지참 | 매너벨트 지참 | 컨디션 | 특이사항 | revision | 수정시각 | 직원확인 revision | 직원확인자 | 직원확인시각.
6. **중요:** 기존 `mdSaveGuardianRequestInternal_` 및 `mdGuardianRequestForBookingInternal_`은 아직 운영 `mdBook_`/`mdSheet_`을 사용한다. 테스트 환경 가드가 추가됐더라도 이 함수들은 테스트 시트로 자동 전환되지 않는다. 해당 함수를 실행하지 말고, 먼저 데이터 접근 계층을 테스트 스프레드시트로 명시적으로 분리해야 한다.
7. 공개 인증/저장 API, 보호자 인증 토큰, 직원 인증 및 테스트 자동화가 완료되기 전까지 PR 병합·배포 금지.

현재 단계: 테스트 환경 가드 코드만 개발 브랜치에 추가됨. 테스트 프로젝트/시트 생성, 함수 실행 및 실제 검증은 하지 않음.
