# 보호자 요청사항 + 직원 체크형 알림장 설계 초안

> 2026-11-01 사용자 피드백 반영. 설계안이며 최종 승인 전. ERP 및 실서비스 미구현.

## 직원 알림장
- **직원 자유서술 코멘트 필드 제외**: 매일 억지로 작성해야 하는 부담 방지.
- 등원/하원 시각은 ERP 예약·출결 기록에서 조회.
- 식사: 완료/일부 섭취/안 먹음/해당 없음.
- 배변: 정상/무름/특이사항/확인 안 됨.
- 활동: 실내놀이/야외놀이/휴식 등 복수 선택.
- 컨디션: 좋음/보통/주의 필요.
- 사진: 선택 첨부. 공개 상태: 미작성/작성중/공개완료.
- 건강 이상·사고는 일일 코멘트와 별개의 **안전·사고 기록 및 즉시 연락 절차**로 관리.

## 보호자 작성 '등원 요청사항'
- 보호자 전용 링크에서 해당 반려견·예약일 확인 후 입력.
- 희망 식사 시간(없음/선택/직접 입력), 사료 지참 여부, 당일 컨디션(평소와 같음/주의 필요), 특이사항(선택 텍스트).
- 예약별로 작성하며 최신 입력 시각·수정 이력 기록. 기존 입력을 무조건 덮어쓰지 않음.
- 직원 확인 상태: 미확인/확인완료. 보호자가 수정하면 다시 미확인으로 변경.
- 보호자 입력은 요청사항이며 **의료 지시나 서비스 제공 확약이 아님**. 약물 투여·응급증상·식이 알레르기 등 안전 관련 사항은 직원의 별도 확인 및 운영규정 필요.
- **수정 마감 우선 검토안(최종 미확정): 보호자가 실제 등원 처리되기 전까지 요청사항을 작성·수정할 수 있도록 한다.** ERP의 실제 등원 상태 전환을 기준으로 수정 입력을 제한하는 방향이며, 등원 후 변경이 필요하면 직원에게 직접 전달하고 직원이 별도 확인·기록하도록 검토한다. 등원 직전 동시 수정·제출 충돌, 직원 확인 후 재수정 시 미확인 상태 복귀, 등원 취소·재예약 시 처리 방식은 추후 설계한다.
- 예약 취소 후 처리, 다견 보호자 권한, 보호자 인증/링크 폐기, 개인정보 보유 기간은 미확정.

## ERP 연동 원칙
- 기존 예약 ID·반려견 ID를 기준으로 연결. 출결·이용권 차감·회계 원장과 기록을 분리.
- 직원 예약 화면에 해당 날짜 보호자 요청사항 및 미확인 배지 표시. 확인 시각·확인 직원 기록.
- 보호자 웹에서 공개완료 직원 알림장과 본인 이용권 잔여 횟수/만료 예정일만 조회. 다른 보호자 데이터 접근 방지.
- 사진은 비공개 접근 제어·보관 및 삭제 정책 필요. 공개 링크는 예측 불가능한 토큰·재발급/폐기 등 검토.
- 실제 배포 전 접근 통제·중복 제출·동시 수정·XSS/입력 검증·개인정보 고지 점검.

## 구현 순서(제안)
1. 기존 ERP 예약·반려견·이용권 데이터 구조와 인증 방식 확인.
2. 보호자 요청사항 저장/조회 및 직원 확인 상태 기능을 테스트 환경에서 구현.
3. 직원 체크형 알림장 작성·공개와 보호자 조회 구현.
4. 사진 및 만료 알림 기능을 별도 단계로 통합.

**이 문서는 기능 설계만 기록하며, 실제 ERP 코드·시트·배포·운영 데이터는 변경하지 않는다.**
