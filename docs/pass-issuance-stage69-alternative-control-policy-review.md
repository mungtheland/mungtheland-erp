# 69단계 동일 계정 대체 통제 정책 검토안

**결정 대기. 현행 환경 게이트는 BLOCKED입니다.** 승인 A 및 읽기 전용 실증 승인은 기존 범위를 유지합니다. 이 검토안은 정책 승인, 원장 초기화 승인 B 또는 TEST 배포 승인 C를 부여하지 않습니다.

## 증빙 경계

동일 Google 계정이 운영 ERP 워크북의 소유 권한을 보유하므로 계정 수준 격리는 `NOT_ISOLATED`입니다. `drive.file`은 특정 OAuth 앱에 허용된 파일의 접근 범위를 제한합니다. 같은 앱에 다른 파일이 허용되면 접근 범위가 넓어질 수 있으며 실제 토큰이 특정 파일 하나에 고정되는 방식은 아닙니다. TEST 파일 ID 고정은 검토한 코드의 요청 대상을 제한합니다.

사용자 제공 실증 출력은 지정 TEST의 메타데이터를 조회해 ID 일치와 `Asia/Seoul`을 확인한 근거입니다. 해당 출력만으로 이전 파일 허용 이력, 실제 계정과 토큰의 유효 범위, 쓰기 또는 배포 권한을 독립적으로 검증할 수 없습니다. 합성 후보와 읽기 검증기의 로컬 테스트를 재사용합니다. 기존 데이터 접근 후보의 정적 감사에서 확인한 넓은 Sheets 범위와 범용 포트 엔진의 잔여 위험은 대체 경로의 승인 근거로 사용하지 않습니다. [사용자 실증 증빙](pass-issuance-stage69-oauth-read-evidence.md) · [후보 번들 권한 감사](pass-issuance-stage69-bundle-permission-audit.md)

## 정책 선택지

| 선택지 | 장점 | 잔여 위험과 필요한 작업 |
| --- | --- | --- |
| 대체 통제 조건부 수용 | 동일 계정으로도 로컬 합성 검증, 향후 단일 TEST 파일 초기화, 합성 후보 배포를 서로 다른 검토 단위로 유지할 수 있습니다. | 계정의 운영 권한은 존속합니다. 앱 오선택, 기존 허용, 범위 혼합, 소스 변조와 배포 오설정이 운영 영향을 일으킬 수 있습니다. 책임 있는 결정권자가 대상·작업·기간·중단 조건을 명시하고 별도로 승인한 뒤 독립 검증이 필요합니다. 현행 게이트는 대체 통제를 격리 요건의 대용으로 인정하지 않으므로 정책 승인만으로 단계 진입이나 실행은 허용되지 않습니다. 별도 정책 반영이 검토되는 경우에도 변경안과 독립 검증이 별도 절차입니다. |
| 계정 수준 격리 요구 유지 | 운영 권한을 가진 계정으로 실제 쓰기와 배포를 진행하는 위험을 계속 막습니다. 현행 게이트와 책임 기준을 유지할 수 있습니다. | 동일 계정을 유지하는 동안 원격 실증은 보류되고 로컬 검증만 가능합니다. 향후 원격 실행에는 운영 파일 접근 권한이 없는 실행 주체와 그 권한 검증이 필요합니다. 현재 계정 유지 조건에서 해당 경로는 선택할 수 없습니다. |

## 통제 및 현재 분류

| 통제 | 분류 | 현재 증빙 또는 남은 요구 |
| --- | --- | --- |
| 최소 권한과 TEST 대상 제한 | 이미 구현 | 기존 읽기 검증기의 단일 파일 선택, 정해진 계정 및 클라이언트 확인, 정확한 ID 고정과 GET 필드 제한. 합성 번들은 Sheets·Drive 접근과 저장 포트를 제외합니다. |
| TEST 읽기 전용 결과 | 사용자 실증 | 지정 파일 ID 및 시간대 조회 성공에 한정합니다. |
| OAuth와 파일 권한 경계 | 독립 검증 필요 | 전용 클라이언트와 유효 범위, 실제로 허용된 파일과 기존 허용 이력을 검토합니다. 운영 데이터나 시크릿을 검증 대상으로 조회하지 않습니다. |
| 운영과 TEST 배포 경계 | 독립 검증 필요 | TEST 워크플로는 코드상 비활성입니다. 운영 수동 워크플로의 실제 대상과 TEST의 분리는 별도 증빙이 필요합니다. |
| Git SHA 및 번들 해시 고정 | 이미 구현 | 로컬 빌드와 해시 재현이 가능합니다. 향후 배포할 정확한 바이트와 승인 C를 결합하는 원격 증빙은 아직 없습니다. |
| 독립 변경 검토 | 독립 검증 필요 | 배포 후보·권한·대상·해시 변경은 재검토합니다. TEST 보호 환경의 독립 필수 검토자와 전용 인증을 별도로 확인합니다. |
| 승인 분리 및 현재 실행 차단 | 이미 구현 | A, 읽기 승인, B, C를 분리합니다. B·C 미승인과 기존 차단을 유지합니다. |
| 사전 스냅샷 및 복구 | 독립 검증 필요 | 전용 대상의 사전·사후 증빙을 보존하고, 지정된 복구 담당자가 사고 시 중단 및 독립 재확인을 조율합니다. 실제 작업의 스냅샷과 복구 실행은 별도로 검토합니다. |
| 동일 계정의 잔여 위험 수용 | 정책 승인 필요 | 정책 결정자, 적용 범위, 유효 기간, 재검토 사유와 철회·중단 조건을 갖춘 별도 결정이 필요합니다. |

검토의 실행 순서와 증빙 양식은 [독립 검증 체크리스트](pass-issuance-stage69-independent-verification-checklist.md)에 있습니다. 승인 순서와 현재 차단 근거는 [70단계 진입 재평가](pass-issuance-stage69-readiness-reassessment.md) 및 [기존 대체 통제 설계](pass-issuance-stage69-alternative-controls.md)를 따릅니다.
