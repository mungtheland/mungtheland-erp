# 69단계 대체 통제 독립 검증 체크리스트

검토자는 요청자와 독립적으로 확인하고, 각 항목에 확인자·시각·검토 리비전·증빙 참조·판정(충족, 미충족, 미검증)을 기록합니다. 현재 문서는 체크리스트 초안입니다. 정책 승인과 실행 승인 B 및 C는 별도로 기록합니다.

## 공통 선행 조건

- [ ] 정책 결정권자와 유효 기간, 허용 TEST 리소스 및 작업, 운영과의 경계, 잔여 위험과 중단 조건을 확인했다.
- [ ] 기존 통제와 로컬 테스트 결과를 확인했다. 사용자 읽기 실증 근거는 지정 TEST ID와 시간대에 한정하고 계정 격리는 `NOT_ISOLATED`로 유지했다.
- [ ] 초기화에 쓸 전용 앱의 정확한 유효 OAuth 범위, 대상 계정, 파일별 허용 경계를 독립 검토했다. 토큰·비밀값·원시 응답을 기록하지 않았으며 운영 대상에 시험 요청을 보내지 않았다.
- [ ] 승인된 이전 독립 증빙이 부족한 경우 해당 항목을 미검증으로 표시했다. 새 원격 확인이나 설정 변경에는 별도 권한을 적용한다.

## 운영 배포 대상의 값 비노출 대조

1. 권한 있는 운영 관리자가 기준 리비전의 `.github/workflows/deploy.yml`에서 실제 대상이 주입되는 설정과 이름을 확인합니다. 저장소 또는 조직 범위의 등록·갱신 메타데이터를 확인해 어느 변경 기록이 현재 구성과 대응하는지 특정합니다.
2. 현재 값과 연결되는 별도의 승인된 비공개 등록 원본 또는 변경 기록이 있을 때만, 운영 관리자가 그 원본 계보를 확인하고 제한된 환경에서 기존 TEST Script ID와 정확한 문자열 일치 여부를 대조합니다. GitHub에서 시크릿 값을 조회하거나 Actions를 실행해 추출하지 않습니다. 설정명, 메타데이터나 오래된 기록만으로 값의 일치를 추정하지 않습니다.
3. 결과는 `DIFFERENT`, `SAME`, `UNVERIFIED` 중 하나와 검토자·시각·워크플로 리비전·비공개 기록 참조만 남깁니다. 실제 값, 해시 및 다른 파생값을 로그나 저장소에 남기지 않습니다. 현재 구성에 연결되는 근거가 없으면 `UNVERIFIED`입니다. `SAME`과 `UNVERIFIED`는 모두 중단 조건입니다. 대상 시크릿 또는 워크플로 변경 후 이전 결과를 재사용하지 않습니다.

이 비교는 현재 수행하지 않았습니다. 성공 증빙이 생겨도 현행 환경 검사기의 수동 워크플로 검토 조건을 임의로 해제하지 않습니다. [기존 배포 절차](pass-issuance-environment-provisioning.md#private-deployment-target-comparison)

## 승인 B — 지정 TEST 워크북만 초기화

- [ ] 승인 기록과 사전 스냅샷의 Spreadsheet ID가 무시되는 로컬 구성의 고정 전용 TEST ID와 정확히 일치한다. 기존 ERP·Guardian 및 임의 대상이 거부됨을 확인했다.
- [ ] 승인된 사전 증빙에서 `Asia/Seoul`, 기존 탭 보존, V2 및 레거시 탭 부재, 고정 숫자 탭 후보 ID `690001`의 충돌 없음을 확인했다.
- [ ] 범위는 `_이용권발급원장V2` 한 탭, A1:P1의 순서가 고정된 헤더 16개, 데이터 행 0건이다. UTF-8 JSON 배열 헤더 SHA-256은 `a36ff1ca249e7fc0c879f1ab86e0b1644db8798fa6dc12ac12312b2220142959`이다.
- [ ] 지정된 복구 담당자와 독립 확인자, 증빙 참조, 승인 B, 사전·사후 확인 조건이 기록됐다. 완료 탭, 헤더 불일치, 부분 상태 또는 응답 불확실 시 중단하고 증빙을 보존한다. 재시도·삭제·수정은 별도 승인까지 보류한다.

## 승인 C — 고정 후보를 지정 TEST Apps Script에 배포

- [ ] 승인 C가 전용 Script ID, 정확한 Git SHA, 후보 번들 SHA-256 및 파일 목록을 함께 지정한다. 임시 빌드에서 재현한 바이트·해시, 예상 매니페스트와 안전한 진입점을 독립 검토했다.
- [ ] 운영 배포와의 비공개 대상 비교가 `DIFFERENT`다. TEST 전용 인증과 대상 검증이 적용되며 운영 인증을 재사용하지 않는다.
- [ ] 보호 환경의 허용 브랜치, 관리자 우회 비활성, 독립 필수 검토자 및 자기 승인 방지가 확인됐다. 승인자가 요청자와 분리되어 있다.
- [ ] 지정된 복구 담당자가 승인된 전용 프로젝트의 사전 소스·매니페스트·배포 상태와 복구 지점을 확인했다. 승인 이후 별도 읽기 검증 계획이 있다. 불일치·타임아웃이면 중단하고 보존하며 재배포 및 복원은 별도 승인 없이는 하지 않는다.

배포 승인 C는 실행 권한이나 초기화 승인 B를 부여하지 않습니다. [승인 C 연결 설계](pass-issuance-stage69-minimum-privilege.md#승인-c와-배포-후보-연결-설계)
