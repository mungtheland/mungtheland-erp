# 보호자 웹 알림장 개발 1단계 — ERP 연동 명세 V0.3

> 2026-11-01. 개발 준비용 초안. 운영 데이터/시트/배포 미변경. 기능은 아직 구현되지 않음.

## 확인된 저장소 구조
- README: Google Sheets + Apps Script, 운영 시트 7개(대시보드, 고객·반려견관리, 예약·등하원관리, 이용권관리, 원생일지, 회계관리, 설정).
- `src/Index.html`: 기존 ERP 직원용 UI(반려견 등록, 예약 등록, 등·하원, 오늘 예약, 이용권, 회계) 확인. 기존 UI를 보호자 공개 페이지로 사용하지 않음.
- 서버측 예약·출결·권한·시트 스키마를 아직 모두 확인하지 못했으므로 함수명·열 번호·테이블 구조를 추정해 운영 코드에 반영하지 않음.

## 기능 범위와 순서
1. 보호자 전용 읽기/쓰기 API를 기존 ERP 내부 관리자 API와 분리.
2. **등원 요청사항**: 예약별 식사 희망시간/사료 지참/**매너벨트 지참 여부**/컨디션/특이사항 작성 및 실제 등원 전 수정.
3. 직원용 **요청사항 확인**: 미작성/미확인/확인완료, 확인한 revision·직원·시각 기록.
4. 직원용 **체크형 알림장**: 식사/배변/활동/컨디션/사진 선택, 직원 자유서술 코멘트 없음.
5. 보호자용 **조회 화면**: 공개완료 알림장, 본인 예약의 출결, 본인 이용권 잔여 회차·만료일.
6. 이후 만료 7일/3일 전 웹 알림 표시, 카카오 알림톡 관리자 승인 발송 연동.

## 최소 데이터 모델 후보 (실제 시트 확인 후 확정)
- GuardianAccess: 보호자ID, 토큰 식별자(원문 토큰 저장 금지), 발급/폐기 시각, 인증실패 횟수, 잠금 시각, 세션 관리.
- GuardianRequest: 요청ID, 예약ID, 반려견ID, 보호자ID, 식사 희망시간, 사료 지참, **매너벨트 지참 여부**, 컨디션, 특이사항, revision, 수정 시각, 직원 확인 revision/직원ID/확인 시각.
- DailyReport: 보고ID, 예약ID, 식사/배변/활동/컨디션 체크, 사진 참조, 상태(미작성/작성중/공개완료), 공개 시각.
- Audit: 작업 종류, 대상ID, 수행자, 시각, 결과. 인증 실패와 개인정보 열람 기록은 최소 수집·보관 정책 검토.
- 기존 원장(예약·출결·이용권·회계)을 단일 진실 공급원으로 사용하고 중복 복제·자동 회차 차감 금지.

## 서버 검증 규칙
- 링크 토큰 + 휴대전화 뒷자리 4자리 방식은 **우선 검토안**으로, 강한 본인확인 수단이 아님. 배포 전 개인정보 위험평가 필수; 위험이 높으면 SMS OTP로 전환.
- 보호자 토큰에 허용된 보호자ID와 예약ID의 소유관계를 서버에서 매 요청 확인. 다른 보호자·반려견 조회 금지.
- 인증 전에는 반려견 이름·사진·예약·이용권 등 식별정보 비노출.
- 보호자 수정은 실제 등원 처리 이전에만 가능. 상태 전환과 요청 저장은 서버측 잠금/버전 검증으로 경합 방지.
- 직원 확인 이후 요청 revision이 증가하면 미확인으로 복귀. 동일 요청 재시도 중복 방지.
- 건강·사고·약물 관련 입력은 자동 처리하지 않고 직원 확인 및 별도 긴급 연락 절차.
- 사진 공개는 비공개 저장·권한검증된 접근 경로를 통해서만 허용. URL에 개인정보 포함 금지.

## 테스트 계획 (테스트 환경만)
- 정상 링크·올바른 4자리, 틀린 4자리 반복/잠금, 폐기된 링크, 다른 보호자 예약 접근.
- 최초 작성, 수정 후 직원 재확인, 등원 상태 변경과 동시 저장, 취소·재예약.
- 공개 전 알림장 보호자 조회 차단, 공개 후 본인만 조회.
- 만료일·잔여 회차는 ERP 원본값과 일치, 원장 값 수정 없음.
- 로그에 토큰·전화번호·민감 특이사항 원문 노출 없음.

## 구현 착수 전 필요한 점검
- 서버측 Apps Script 파일 및 예약/반려견/보호자/이용권 실제 필드·식별자 확인.
- 보호자 웹 배포 방식과 접근 권한, 세션 유지 및 링크 폐기 설계.
- 사진 저장소·개인정보 보유/삭제 정책 및 인증 방식 보안 검토.
- 기능 개발은 별도 브랜치/테스트 시트에서 수행하고, 운영 배포는 별도 승인 후.

### 매너벨트 운영 메모 (추가 설계, 미확정)
- 마킹이 심한 반려견 등 매너벨트 필수 대상은 **직원이 ERP에서 별도로 지정**하는 방안을 검토한다.
- 보호자 요청사항에 지참 여부를 선택하게 하고, 필수 대상인데 미지참이면 직원 화면에 **확인 필요** 표시를 검토한다.
- 보호자의 체크만으로 실제 지참 여부가 확인된 것으로 간주하지 않는다. 등원 시 직원이 실물 확인하도록 설계한다.
- 미지참 시 대여·판매·등원 가능 여부 및 위생 관리 기준은 별도 운영규정으로 결정하며, 현재 자동으로 등원을 거부하지 않는다.
