# 보호자 요청사항 구현 현황 및 테스트 체크리스트

- 브랜치: feature/guardian-request-prototype
- 파일: prototypes/guardian-request.html (화면 시안), src/GuardianRequest.js (입력값 검증)
- 현재 코드의 검증 항목: 사료 지참 yes/no, 매너벨트 yes/no/na, 컨디션 normal/caution, 특이사항 최대 500자.
- 아직 구현하지 않은 것: 식사시간 서버 검증, 인증/세션, 보호자와 예약 소유 관계 검증, 저장 및 수정, 실제 등원 이후 잠금, 직원 확인 상태, 실서비스 배포.
- **테스트 데이터 작성 및 배포 없음.** 시트 자동 생성 없음.

## 다음 구현 작업의 안전 기준
1. 테스트용 스프레드시트/스크립트 연결을 먼저 확인한다.
2. 직원 API와 보호자 공개 API를 분리하고, 보호자 요청별 인증·예약 소유관계를 서버에서 확인한다.
3. 저장은 예약의 실제 등원시간·상태를 재검증한 뒤 잠금 안에서 수행한다.
4. revision 충돌을 검증하고 직원 확인 상태를 무효화한다.
5. 인증 시도 제한과 토큰 폐기, 사진·특이사항 접근 통제를 검증한 후에만 배포를 검토한다.

## 확인 필요
기존 운영 스크립트의 추가 파일 및 기존 함수와의 중복 여부를 확인해야 한다. main 브랜치 병합 또는 Apps Script 배포는 하지 않는다.
