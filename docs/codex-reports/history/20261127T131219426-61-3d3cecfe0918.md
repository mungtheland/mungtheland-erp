## Change summary

- Ledger contract fields: issuanceRequestId, idempotencyKey, paymentReference, productId, catalogVersion, totalUses, petId, guardianId, passId, issuanceStatus, requestedAt, committedAt, attemptCount, lastErrorCode, sourceChannel and auditReference.
- State flow is VALIDATED to PENDING to COMMITTED; conflicts move to NEEDS_REVIEW; FAILED_FINAL is terminal. NEEDS_REVIEW returns to PENDING only with audited recovery.
- Same request and same payment returns the original committed pass; changed payment under one request or reused payment under another request is blocked for review.
- Write simulation stages pending ledger, synthetic pass and committed marker. Pass-only, committed-ledger-only, mismatched pair and ambiguous state require review rather than reissue.
- Injected failures before and after each stage leave recoverable synthetic states; committed response loss resolves by lookup. 21 focused synthetic tests cover retries, concurrency and fault cases.
- Concurrent calls are serialized by a process-local promise queue. This does not prove Apps Script cross-execution or multi-host locking.
- Architecture A: Sheets remains the current balance source and adds an append-only issuance journal with LockService and reconciliation; best current compatibility, but not a multi-sheet transaction. Recommended for later implementation only.
- Architecture B: Firestore ledger with Sheets projection adds source split and projection recovery; its transaction cannot atomically commit a Sheets row.
- Architecture C: dual Sheets and Firestore writes has the highest partial-failure and reconciliation burden without a distributed transaction; not recommended.
- Added a synthetic-only issuance ledger with serialized retries and recovery reconciliation. Preserved mdRegisterPass and added no live store adapter.
