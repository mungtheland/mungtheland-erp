## Change summary

- 고정된 테스트 프로젝트 경로와 승인된 두 출석 문서만 GET으로 조회했다. 컬렉션 목록, 쿼리, 데이터베이스 메타데이터, 쓰기, 삭제 요청은 하지 않았다.
- 현재 ADC는 일반 사용자 형식이라 기존 Firestore 진단기의 서비스 계정 가장 ADC 사전검사는 BLOCKED였다. 설정은 바꾸지 않고 기존 gcloud 사용자 인증으로 승인된 Firestore 읽기 주체에 datastore 범위 토큰을 요청해 정확한 개별 GET을 수행했다. Sheets는 승인된 테스트 읽기 주체와 spreadsheets.readonly 범위로 읽었다. 비밀정보는 출력하거나 저장하지 않았다.
- 두 승인 문서는 모두 HTTP 200, 하원 완료, 등원 1회 후 하원 1회, 이벤트 총 2건이었다. 문서와 이벤트 예약 연결, 상태, 시각 형식 및 Asia/Seoul 변환이 확인됐고 중복 이벤트는 없었다. 두 문서의 updateTime은 앞선 44·47단계 보고서와 일치했다.
- Sheets 지정 세 시트는 예약 6건, 이용권 6건, 변동이력 3건이며 이중 스냅샷이 동일했다. 두 Firestore 예약 ID는 예약 시트에 각각 0건이어서 교차 상태는 NO_MATCH 2건이다. 이는 MISMATCH로 분류하지 않았다.
- 두 Firestore 문서의 passDeduction 상태는 반환되지 않았다. Sheets 예약 행도 일치하지 않아 이용권 차감 상태는 두 건 모두 BLOCKED이며 완료로 추정하지 않았다.
- 읽기 전용 교차검증기와 테스트를 추가했다. 문서 경로 허용 목록, 이벤트·상태·KST 검사, 중복 검출, 정확 ID 매칭, NO_MATCH 및 NEEDS_REVIEW/BLOCKED 처리를 검증한다.
