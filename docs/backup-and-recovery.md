# 멍더랜드 ERP 운영 데이터 백업 및 복구 절차

## 백업 범위
원본 Google 스프레드시트(고객·반려견관리, 예약·등하원관리, 이용권관리, 원생일지, 회계관리, 설정, 대시보드 및 _로 시작하는 변경·정산 이력 탭 포함)를 **파일 전체** 복사한다. 숨김 시트와 수식, 서식, 데이터 유효성도 포함해야 한다. CSV로 각 탭만 저장하는 방식은 복구용 전체 백업을 대체하지 못한다.

## 운영 전 확인
1. 원본 파일 소유자 계정의 Google Drive에서 **파일 > 사본 만들기**로 별도 백업 파일을 생성한다.
2. 이름은 `멍더랜드ERP_백업_YYYY-MM-DD_HH-mm` 형식으로 한다. 운영자 2명 외 접근을 제한하고, 원본보다 권한이 넓어지지 않게 확인한다.
3. 백업 파일에서 모든 탭(숨김 탭 포함), 마지막 기록, 수식 및 데이터 유효성을 확인한다.
4. **복구 연습은 원본이 아닌 별도 사본에서만** 수행한다.
5. 백업 실패·데이터 오류 시에는 예약 변경, 이용권 차감·복구, 정산 확정·지급기록 입력을 중단하고 원인을 확인한다.

## 권장 주기 및 보존
- 운영일 종료 후 1회 전체 백업. 정산 확정 또는 대량 수정 직전 추가 백업.
- 최근 일별 백업 30개, 월말 백업 12개를 권장한다. 고객 연락처·건강정보가 포함되므로 업무상 필요 이상 장기 보존하지 않는다.
- 보존기간과 개인정보 파기 정책을 확정한 후 자동 삭제 정책을 적용한다.

## 복구 시 주의
- 가장 최근 정상 백업을 **새 파일로 복사**해 먼저 확인한다.
- 장애 시각 이후 변경된 예약·등하원·이용권·회계 내역을 별도 대조한다.
- 복원 파일로 전환하려면 Apps Script의 `MD_SPREADSHEET_ID`가 원본 파일 ID로 고정되어 있다는 점을 고려해야 한다. ID 변경·재배포 전까지 복구 사본을 운영 원장으로 사용한다고 가정하지 않는다.
- 실데이터를 원본에 덮어쓰거나 원본 파일을 삭제하는 복구는 반드시 별도 승인 후 수행한다.

## 현재 구현 상태
이 문서는 수동 백업 및 복구 운영 절차다. **자동 백업 실행, 성공 알림, 보존기간에 따른 자동 삭제는 아직 구현·검증되지 않았다.** GitHub Actions의 격리 테스트 통과는 Google Drive 백업 성공을 의미하지 않는다.
