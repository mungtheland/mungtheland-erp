## 권장 처리 흐름
1. Tally 입소 신청서 및 이용상품 신청서 제출: 각 응답의 submission ID와 form ID 보존
2. Tally 원본 시트(별도 파일)에서 **읽기 전용** 수집. 두 파일/탭의 정확한 ID·헤더는 연결 전에 검증
3. 별도 테스트 스프레드시트의 접수대장에 원본 ID 기준 upsert, 재실행 멱등성 보장
4. 보호자 연락처·반려견명만으로 자동 병합하지 않음. 신청 간 연결은 명시적 신청번호 또는 직원 확인
5. 입소 심사(물림/공격, 질병/접종, 계약서/서명), 상품/할인 심사(결합·다견 중복 정책 확인)
6. 승인 상태: 접수 → 심사중 → 보류/거절/승인 → 결제확인 → ERP반영
7. 승인/입금 검증 이후에만 기존 ERP 등록 API를 통하여 기록. 고객/이용권/회계는 별도 승인 단계
8. 실패 재처리 시 외부 submission ID + 처리유형에 대한 중복 방지 및 감사 로그
9. 테스트 통과 후 운영자 승인과 백업·복원 검증을 거쳐 배포
