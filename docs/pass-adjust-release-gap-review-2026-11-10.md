# 이용권 차감·복구 운영 적용 전 차이 분석 (2026-11-10)

## 범위 및 증거
- 운영 기준: `main/src/PassAdjust.js`, `main/src/Passes.js`, `main/src/OperatorAudit.js`.
- 격리 검증: `feature/guardian-request-prototype/guardian-test-app/`.
- 사용자 제공 Apps Script 실행 로그: 정상 차감·복구 회귀 16/16, 예외 10/10, 강제 오류 롤백 12/12, 동시 차감 최종 상태 5/5.
- 본 문서는 **코드 검토 기록**이며 운영 코드 변경·운영 배포 승인이 아니다.

## 운영 코드에서 확인된 차이
1. **ID 유일성**: 운영 코드는 `mdFindById_`로 첫 일치 행을 조회한다. 격리 코드는 중복 예약 ID 또는 이용권 ID가 있으면 거부한다. 운영 데이터가 중복될 때 잘못된 행 변경 위험이 있다.
2. **이력/차감상태 무결성**: 운영 코드의 `if(deduction==='차감'||net===1)return alreadyDeducted`는 상태와 이력이 서로 불일치해도 정상 중복으로 취급한다. 격리 코드는 불일치 시 중단하고, 기존 차감의 연결 이용권도 검사한다.
3. **롤백 이력 식별**: 운영 코드는 append 후 `getLastRow()`를 기록해 실패 시 해당 행 삭제를 시도한다. 격리 코드는 생성한 `entryId`로 행을 찾아 삭제하고, 변경된 값 및 이력 제거를 재검증한다.
4. **잠금 및 시트 반영**: 격리 코드는 잠금 획득 직후 `SpreadsheetApp.flush()`를 호출한다. 테스트에서는 정상 결과를 확인했으나 Google Sheets의 여러 시트 쓰기가 원자적 트랜잭션임을 보장하지는 않는다.
5. **테스트 전용 기능**: `testFailurePoint`, `AFTER_LEDGER_APPEND`, `AFTER_PASS_UPDATE` 및 `RSV-RB-` / `PASS-RB-` 접두어 조건은 운영 코드에 복사하지 않는다.
